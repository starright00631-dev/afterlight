# Afterlight: AI Usage Disclosure

## Nature of these materials

This disclosure accompanies **Afterlight 3.4.0**. To protect privacy, this document, the new `ai-logs/` materials and the standalone submission ZIP exclude original conversations, private prompts, account information and API keys. The public repository retains existing maintenance documentation and required attribution; these exclusions do not imply that its history has been rewritten.

The files in `ai-logs/` are **reconstructed prompt examples** based on the final implementation. They illustrate reusable constraints and acceptance criteria. They are not original transcripts, execution logs or a development timeline, and do not establish that these particular prompts were used. The competition requests conversation records; the organizer has not confirmed whether this alternative is acceptable.

## AI involvement

| Documentation | Helped explain usage, boundaries, environment requirements and submission materials | README, usage documentation and this disclosure |

The project owner requested one complete product in which the night setting supports practical study and planning. Components needed a useful purpose, and planning needed more than a decorative display. The application was refined around those requirements. AI suggestions and generated material were checked against source code, automated checks and actual runtime behavior; generated text was not treated as evidence that a feature worked.

## Verification of the result

The accompanying verification record reports **275 passing Node tests**, reconciliation of lighting, workspace and calendar exports, local startup from an extracted copy, a static browser build, and desktop and small-screen checks. The original release also passed **6 packaging regression tests**; those are release checks, not tests of a maintainer packager included in this submission. These results evaluate software behavior, not users' learning outcomes.

Lighting values come from a deterministic model. Physical observations must be entered separately by the user. Room and material images provide visual context and contribute no calculated illumination. Lamp coordinates, fields, paths, readings and controls are generated by the running application. Screenshots show the application; example tasks and data remain examples.

## Known boundaries

- The lighting table is a Canvas 2D projection with an ideal direct-light model. It does not include a complete 3D renderer, reflections, ambient light or physical-room calibration.
- The planner uses a deterministic heuristic and requires explicit acceptance. It does not synchronize calendar accounts or establish productivity gains.
- Review uses self-assessment and fixed 1-, 3- and 7-day revisit rules. It does not grade understanding or establish mastery or learning gains.
- PDF intake retains extractable text. It provides neither OCR nor an original-page viewer; scanned documents require a transcript.
- The hosted demo disables model-provider connections. Optional local assistance requires a compatible configured provider; release checks did not establish successful real model inference.
- Elapsed focus time, user-reported outcomes and task estimates are separate records. The quiet timer does not establish sleep or health benefits.
